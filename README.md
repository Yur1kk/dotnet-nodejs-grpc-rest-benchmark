ДОДАТОК А

Розширена інструкція користувача та архітектурний опис структури проекту

1. ЗАГАЛЬНИЙ ОПИС ПРОЕКТУ

Даний репозиторій містить вихідний код, інфраструктурні маніфести та скрипти тестування для проведення порівняльного аналізу продуктивності мікросервісних архітектур. Проект реалізовано на двох технологічних стеках: Node.js (інтерпретована подійно-орієнтована платформа) та .NET 8 (компільована багатопотокова платформа). Міжсервісна взаємодія реалізована двома протоколами: HTTP/1.1 REST та HTTP/2 gRPC.

2. СТРУКТУРА ДИРЕКТОРІЙ ТА ОПИС ФАЙЛІВ

Коренева директорія проекту поділена на дві незалежні екосистеми:
- /Cloud-Distributed/ — мікросервіси, реалізовані на базі Node.js (NestJS).
- /Cloud-Distributed-CSharp/ — мікросервіси, реалізовані на базі .NET 8 (ASP.NET Core).

Обидві директорії мають ідентичну внутрішню структуру для забезпечення симетрії експерименту:

2.1. Директорія /deploy-db/ (Інфраструктурний рівень)
- docker-compose.yml — маніфест для розгортання реляційної бази даних PostgreSQL та системи телеметрії (InfluxDB, Grafana).
- /grafana/provisioning/ — директорія, що містить файли автоматичного налаштування джерел даних (datasource.yml) та дашбордів для Grafana без необхідності ручного втручання.
- /influxdb/init/create-databases.sh — скрипт автоматичної ініціалізації ізольованих баз даних (k6_rest, k6_rpc) в InfluxDB для уникнення змішування метрик під час тестування.

2.2. Директорія /deploy-users/ (Мікросервіс "Користувачі")
- /users-service-rest/ — вихідний код сервісу користувачів, що надає REST API інтерфейс.
- /users-service-rpc/ — вихідний код сервісу користувачів, що надає gRPC інтерфейс за допомогою Protobuf контрактів.
- docker-compose.yml — маніфест для незалежного запуску мікросервісів даного домену.

2.3. Директорія /deploy-orders/ (Мікросервіс "Замовлення")
- /orders-service-rest/ — вихідний код сервісу замовлень. Містить логіку синхронного REST-запиту до сервісу користувачів для валідації ідентифікатора клієнта перед створенням замовлення.
- /orders-service-rpc/ — вихідний код сервісу замовлень з імплементацією gRPC-клієнта для внутрішньої взаємодії з сервісом користувачів.
- docker-compose.yml — маніфест оркестрації контейнерів домену замовлень.

2.4. Директорія /deploy-gateway/ (Рівень маршрутизації та тестування)
- /rest-api-gateway/ — вихідний код єдиної точки входу (API Gateway), що виконує роль проксі-сервера для REST-архітектури.
- /rpc-api-gateway/ — вихідний код шлюзу, який приймає зовнішні REST-запити та виконує трансляцію протоколів, перетворюючи їх у gRPC-виклики до внутрішніх мікросервісів.
- /k6-tests/ — директорія зі скриптами навантажувального тестування (наприклад, test-rest-vus.js та test-rpc-vus.js), які описують життєвий цикл віртуальних користувачів.
- docker-compose.yml — маніфест для запуску API-шлюзів.
- run-tests.sh — ключовий командний скрипт для автоматизації процесу тестування.

2.5. Кореневі файли
- .gitignore — файл виключень для системи контролю версій Git, що запобігає індексації зібраних бінарних файлів (bin/, obj/) та директорій з модулями (node_modules/).
- README.md — даний документ.

3. ІНСТРУКЦІЯ З ЛОКАЛЬНОГО РОЗГОРТАННЯ ТА ЗАПУСКУ

Для успішного запуску проекту необхідно переконатися у наявності встановленого програмного забезпечення Docker Desktop.

Крок 1. Запуск інфраструктурного рівня
1. Відкрийте термінал.
2. Перейдіть до інфраструктурної директорії:
   cd Cloud-Distributed/deploy-db
3. Виконайте команду для фонового запуску бази даних та моніторингу:
   docker-compose up -d

Крок 2. Запуск мікросервісів та API-шлюзів (на прикладі Node.js середовища)
1. Перейдіть до директорії сервісу користувачів та запустіть контейнери:
   cd ../deploy-users
   docker-compose up -d --build
2. Перейдіть до директорії сервісу замовлень та запустіть контейнери:
   cd ../deploy-orders
   docker-compose up -d --build
3. Перейдіть до директорії API-шлюзів та запустіть контейнери:
   cd ../deploy-gateway
   docker-compose up -d --build

Крок 2.1. Ініціалізація та первинне наповнення баз даних (Database Seeding)
1. Для екосистеми .NET 8 (Cloud-Distributed-CSharp) застосування міграцій Entity Framework Core та наповнення тестовими даними (seeding) відбуваються абсолютно автоматично під час старту додатків. Додаткові ручні дії не потрібні.
2. Для екосистеми Node.js (Cloud-Distributed) після запуску контейнерів необхідно вручну виконати генерацію початкових даних всередині запущених контейнерів за допомогою наступних команд:
   docker exec -it diploma_users_rest npm run seed
   docker exec -it diploma_users_rpc npm run seed
   docker exec -it diploma_orders_rest npm run seed
   docker exec -it diploma_orders_rpc npm run seed

Крок 3. Налаштування телеметрії
1. База даних часових рядів InfluxDB автоматично ініціалізується завдяки вмонтованому скрипту create-databases.sh під час старту.
2. У разі необхідності ручного створення баз даних (наприклад, при розгортанні на чисті віртуальні машини в хмарі), виконайте наступні команди:
   curl -XPOST "http://localhost:8086/query" --data-urlencode "q=CREATE DATABASE k6_rest"
   curl -XPOST "http://localhost:8086/query" --data-urlencode "q=CREATE DATABASE k6_rpc"
3. Відкрийте веб-браузер та перейдіть за адресою http://localhost:3006 (порт доступу до графічного інтерфейсу Grafana).
4. Дашборди продуктивності підвантажуються автоматично.

Крок 4. Запуск навантажувального тестування
1. Перебуваючи у директорії /deploy-gateway/, переконайтеся у наявності прав на виконання скрипта:
   chmod +x run-tests.sh
2. Для запуску тестування з визначеною кількістю віртуальних користувачів (наприклад, 500 VUs), використайте змінну оточення VUS:
   VUS=500 ./run-tests.sh
3. Для запуску тестування виключно через API-шлюз передайте відповідний аргумент:
   VUS=500 ./run-tests.sh gateway

4. АНАЛІЗ РЕЗУЛЬТАТІВ

У процесі виконання скрипта run-tests.sh, інструмент k6 генерує метрики (затримки p95/p99, пропускну здатність RPS, відсоток помилок) та експортує їх до бази InfluxDB. Результати відображаються у графічному інтерфейсі Grafana в режимі реального часу. Після завершення тестів для екосистеми Node.js, необхідно зупинити контейнери командою `docker-compose down` у відповідних директоріях, та повторити Кроки 2-4 для директорії Cloud-Distributed-CSharp.
